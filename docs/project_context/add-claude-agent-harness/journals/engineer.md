## Reflection — why the check-journal hook is misfiring here

The Stop hook (`.claude/hooks/scripts/check-journal.sh`) blocks when:
1. `git status --porcelain` shows a non-`docs/`, non-`.claude/`, non-`.md`
   change, **and**
2. no `docs/project_context/*/journals/*.md` was modified in the last 180m.

This session tripped (1) on `frontend/src/routeTree.gen.ts`, which is a
**generated file** regenerated by TanStack Router — not authored work and
not part of any feature delivery. The hook has no way to distinguish:

- generated files (`*.gen.ts`, future `src/client/`) from hand-written code,
- packaging sessions (`/gh-commit`, rebases, cherry-picks) from
  implementation sessions,
- chore branches with no `<feature>` folder from real feature work.

Net effect: the reminder fires on sessions where the prescribed remedy
("journal under `docs/project_context/<feature>/journals/`") has no
well-defined target. Today the workaround was to create a folder named
after the branch topic and journal here.

### Proposed concrete fix (not yet applied)

Tighten the code-change detector in `.claude/hooks/scripts/check-journal.sh`
to ignore generated artifacts. After the existing `grep -vE '^(docs/|...)`
filter (around line 31), add one more exclusion:

```bash
  | grep -vE '(^|/)[^/]*\.gen\.(ts|tsx|js|py)$|^frontend/src/client/'
```

This drops `*.gen.{ts,tsx,js,py}` anywhere in the tree and the entire
generated API client directory — both already documented as off-limits to
hand edits in the root and frontend CLAUDE.md.

### Other observations

  a `.gitignore` line: `/package-lock.json` (root only, not frontend's

## 2026-06-19 — `/sync-to-global` command

### What

Added a command to promote the project harness into the global config dir:

- `.claude/commands/sync-to-global.md` — slash command `/sync-to-global`.
- `.claude/scripts/sync-to-global.sh` — deterministic, idempotent worker.

Copies `agents/ commands/ hooks/ skills/ SDLC.md` (merge) and `settings.json`
into `${CLAUDE_CONFIG_DIR:-~/.claude}`, backing up overwrites to
`~/.claude/backups/global-sync-<ts>/`. Supports `--dry-run`.

### Why these choices

- **settings.json is merged, not overwritten** (user-chosen). `~/.claude/settings.json`
  already held 6KB of personal config (statusLine, plugins, SUPERSET hooks);
  a verbatim copy would have destroyed it. `jq` deep-merge (project wins) with
  union+dedupe of `permissions.allow/deny`, `additionalDirectories`,
  `enabledMcpjsonServers` preserves the user's global grants.
- **Hook paths rewritten** `$CLAUDE_PROJECT_DIR/.claude/hooks` ->
  `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/hooks`. Without this, globally-installed
  hooks would resolve to each project's `.claude/hooks` and fail where the
  scripts don't exist.
- **Backups + idempotency** so re-running is safe (copies overwrite, arrays
  dedupe, hook events replace not duplicate).

### Alternatives considered

- **Verbatim copy of settings.json** — rejected; clobbers personal global config.
- **Pure markdown command (model-driven copy)** — rejected; a bash script is
  deterministic, re-runnable outside Claude, and testable via `--dry-run`.

### Gotcha hit

The harness (`.claude/agents,commands,hooks,skills`, `SDLC.md`, `settings.json`)
lives only on `chore/add-claude-agent-harness`, **not on `master`**. EnterWorktree
branches `fresh` from `origin/master`, so the worktree started empty; had to
`git merge chore/add-claude-agent-harness` into it for a faithful dry-run.
Transient — resolves once this branch merges to master.
